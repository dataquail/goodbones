---
title: Adoption
description: Turn rules on in an existing repository and tighten them over time.
---

To adopt rules in a repository that already breaks them, record today's violations in a
**baseline**, cap the untightened parts with `limits`, and track reach with `coverage`. Each is a
ratchet: it only tightens unless someone edits the manifest.

## Baseline

A baseline is a file of violations the code already has. They stop reporting; anything new
reports immediately.

```yaml
baseline: .architecture-baseline.json
```

```bash
architecture baseline    # record what the repository currently violates
architecture check       # passes, carrying those and refusing anything new
```

- **Entries ignore line numbers.** Each is a fingerprint, `kind|rule|file|subject`, so reformatting
  or moving code doesn't break a match.
- **A stale entry fails `check`.** When you fix a violation, `check` fails until you remove its
  entry by rerunning `architecture baseline`. So the count only goes down.

```
2 baseline entries no longer fire. The code was fixed; prune them:
  import|domain-isolation|src/modules/user/domain/user.root.ts|packages/database/src/index.ts
```

`check` reports how much you're carrying: `1284 files, 0 violations, 37 carried by the baseline`.

:::tip
With only a handful of violations, fix them instead. If a case is genuinely correct, say so in the
manifest (an `except`, an allowlist entry, a `requiresNot`) rather than baselining it forever.
:::

## `limits`

Two manifest markers say "not this part yet":
[`partial`](/goodbones/architecture-rules/manifest/inheritance/) on a folder, and
`unrestricted: true` on an `imports` block (no allowlist, only prohibitions). `limits` caps how many
of those you have, and sets floors and ceilings on what `check` measures.

```yaml
limits:
  unrestricted: 3 # at most three tiers may say `unrestricted: true`
  partial: 1 # at most one folder may be `partial`
  coverage: # floors, as fractions of the files walked
    imports: 0.9
    structure: 0.8
    members: 0.2
    surface: 0.5
    graph: 1
  unreached: # ceilings, as counts of files a family does not reach
    structure: 40
    surface: 12
  outside: ["~/legacy-api/**"] # files none of these numbers count
  conformance: # ceilings, as counts
    residue: 0
    vacant: 2
    slack: 14
    concentration: 0
```

| Key            | Checked by                      | Fails when                                         |
| -------------- | ------------------------------- | -------------------------------------------------- |
| `unrestricted` | the plugin and `check`, at load | more `unrestricted` tiers than allowed; names them |
| `partial`      | the plugin and `check`, at load | more `partial` folders than allowed; names them    |
| `coverage`     | `check`                         | a family's fraction is under its floor             |
| `unreached`    | `check`                         | a family leaves more files unreached than allowed  |
| `conformance`  | `check`                         | a measure's count is over its ceiling              |

**Coverage floors.** A file counts toward a family when:

| Family      | A file counts when                                                         |
| ----------- | -------------------------------------------------------------------------- |
| `imports`   | an import allowlist selects it (an `unrestricted` tier has none)           |
| `structure` | its folder's files are enumerated by name (an `open` folder doesn't count) |
| `members`   | a `members` rule selects it                                                |
| `surface`   | a `surface` rule selects it                                                |
| `graph`     | it is in the scope of a `cycles` or `orphans` rule                         |

**Unreached ceilings** hold the same reach as a count: the files a family does not reach. Prefer
them where the tree is changing.

- A fraction moves when the tree does. Deleting files a rule reached lowers it, and so does a
  folder the policy leaves open growing, though the policy reaches exactly what it did.
- The count moves only when a file no rule reaches is added. Deleting reached files leaves it
  alone, and deleting unreached ones lowers it.
- State either or both per family. `architecture coverage` prints the count beside the fraction,
  and says when a ceiling can be lowered.

**`outside`** names files none of these numbers count: a package that is open by design, such as
one being strangled, or a vendored tree. Every rule still judges those files. They are left out
of the coverage floors, the unreached ceilings and `residue`.

**Conformance ceilings** cap the measures
[`architecture conformance`](/goodbones/architecture-rules/enforcement/conformance/) reports:

| Measure         | Counts                                                        |
| --------------- | ------------------------------------------------------------- |
| `residue`       | files no family reaches                                       |
| `vacant`        | nodes that state an import allowlist and select no file       |
| `slack`         | allowances no import uses                                     |
| `concentration` | `defs` entries used at fewer than half the nodes granted them |

Set each ceiling to today's count and lower it as the count falls. Raise floors as coverage rises.
A ceiling going up is a signal, not noise: slack that rose because an allowance lost its only
user is fixed by deleting the allowance.
For cycles, use a [`cycles` rule](/goodbones/architecture-rules/manifest/graph/) and baseline each one.

## `coverage`

`architecture coverage` prints the numbers `check` compares against the floors.

```
$ architecture coverage packages

61 files under packages

  imports       61/61  100%  under an import allowlist  ≥ 100% ✓
  structure     61/61  100%  in an enumerated folder (0 in an open one, 0 in none)
  members       21/61   34%  selected by a members rule
  surface       58/61   95%  selected by a surface rule  3 unreached ≤ 3 ✓
  graph         48/61   78%  in a cycles or orphans scope

  unrestricted tiers: (none)
  partial tiers:      (none)
```

Coverage measures reach, not correctness. To test a rule, [plant the violation](/goodbones/architecture-rules/enforcement/probes/).
