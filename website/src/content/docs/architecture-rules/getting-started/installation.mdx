import { Steps } from "@astrojs/starlight/components";

Add a first policy to a TypeScript repository and watch it catch a bad import.

<Steps>

1. Install the oxlint plugin and the CLI:

   ```bash
   pnpm add -D @goodbones/oxlint   # editor and CI feedback through oxlint
   pnpm add -D @goodbones/cli      # the `architecture` command
   ```

2. Enable the plugin's rules in `.oxlintrc.json`:

   ```json
   {
     "jsPlugins": [{ "name": "architecture", "specifier": "@goodbones/oxlint" }],
     "rules": {
       "architecture/imports": "error",
       "architecture/exports": "error",
       "architecture/members": "error",
       "architecture/structure": "error",
       "architecture/surface": "error"
     }
   }
   ```

   The plugin also has an `architecture/campaigns` rule; see
   [Campaigns installation](/goodbones/campaigns/getting-started/installation/).

3. Write `architecture.yaml` at the repository root:

   ```yaml
   # yaml-language-server: $schema=https://dataquail.github.io/goodbones/schema/architecture.schema.json
   resolve:
     scopes:
       - files: ""
         language: typescript
         options: { tsconfig: tsconfig.json }
     unresolved: error
   aliases:
     "@": src
   tree:
     "@/domain/":
       imports:
         message: "domain/ may not reach the framework."
         reset: true
         external: [effect]
         allow: ["@/domain/**"]
       children:
         "*.ts": {}
   ```

   This says:

   - `src/domain/` admits only `.ts` files.
   - Files there may import only from `src/domain/` and `effect`. Anything else fails with the message.
   - Every import in the repository must resolve to a file.

   Or run `pnpm exec architecture init` for a starter, or
   [infer one](/goodbones/architecture-rules/getting-started/infer/) from your code.

4. Plant a violation and watch it fail:

   ```bash
   echo 'import "express";' > src/domain/probe.ts
   pnpm oxlint src
   rm src/domain/probe.ts
   ```

5. Run the CLI to check the whole repository, including the
   [`graph`](/goodbones/architecture-rules/manifest/graph/) rules the plugin cannot see:

   ```bash
   pnpm exec architecture check
   ```

</Steps>

## Errors at load

The plugin reads the manifest when oxlint starts. A malformed manifest stops the lint with every
error at once, each naming its file, line and column. A rule that can no longer match anything
also stops it; see [probes](/goodbones/architecture-rules/enforcement/probes/).

## Editor completion

The first-line comment points your YAML extension (such as VS Code's) at the manifest's schema, so
it completes keys and flags misspellings as you type.

:::caution
If you load the plugin from a workspace package instead of npm, build it before linting (for
example in a `prelint` script). oxlint loads the compiled output, so a stale build enforces a stale
policy and still passes.
:::
