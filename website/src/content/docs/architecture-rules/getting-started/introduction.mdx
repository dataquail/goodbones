Architecture Rules lets you write your repository's architecture in one file, `architecture.yaml`,
and enforce it with an oxlint plugin and a CLI. Reach for it when you want import boundaries,
folder layouts and naming rules checked on every change instead of in code review.

## What it enforces

Each question below is answered by one family of rules, each with its own page.

| Question                                      | Family                                                           |
| --------------------------------------------- | ---------------------------------------------------------------- |
| What may this folder import?                  | [`imports`](/goodbones/architecture-rules/manifest/imports/)     |
| Who may import it?                            | [`importedBy`](/goodbones/architecture-rules/manifest/imports/)  |
| Which importers may use this exported symbol? | [`exports`](/goodbones/architecture-rules/manifest/exports/)     |
| Which names may this file declare or call?    | [`members`](/goodbones/architecture-rules/manifest/members/)     |
| What may this file export?                    | [`surface`](/goodbones/architecture-rules/manifest/surface/)     |
| Which files may live in this folder?          | [`structure`](/goodbones/architecture-rules/manifest/structure/) |
| What may they be called?                      | [`structure`](/goodbones/architecture-rules/manifest/structure/) |
| Which sibling files does this file require?   | [`structure`](/goodbones/architecture-rules/manifest/structure/) |
| Is there an import cycle?                     | [`graph`](/goodbones/architecture-rules/manifest/graph/)         |
| Does anything import this file?               | [`graph`](/goodbones/architecture-rules/manifest/graph/)         |
| Can this layer reach that one, by any route?  | [`graph`](/goodbones/architecture-rules/manifest/graph/)         |

The oxlint plugin and the CLI both check the first five. `graph` needs the whole repository, so
only the [CLI](/goodbones/architecture-rules/enforcement/cli/) checks it. To adopt rules on an
existing codebase, see [adoption](/goodbones/architecture-rules/enforcement/adoption/).

## A manifest is a tree

The manifest reads like a directory listing. Everything about a folder is written at that folder,
and its subfolders inherit it:

```yaml
"@/modules/{module}/domain/":
  imports:
    reset: true
    external: [effect]
    allow: ["@/modules/{module}/domain/**"]
  children:
    "*.root.ts": { requires: ["{base}.root.test.ts"] }
```

This says `domain/` may import only itself and `effect`, and every `*.root.ts` needs a test beside it.

## Two guarantees

- **Rules match resolved files.** An import is resolved through your `tsconfig` paths and workspace
  links before any rule sees it. An import that cannot be resolved is an error, not a skip.
  See [resolution](/goodbones/architecture-rules/enforcement/resolution/).
- **Every rule proves it can fire.** Each rule is tested against a generated violation when it
  loads, and the plugin refuses to load if one no longer matches anything.
  See [probes](/goodbones/architecture-rules/enforcement/probes/).
