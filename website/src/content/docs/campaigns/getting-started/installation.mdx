Set up campaigns once you have Architecture Rules
[installed](/goodbones/architecture-rules/getting-started/installation/). A campaign lives in
the same `architecture.yaml`.

## Install

Campaigns are a separate package. Add it beside the hosts you already use:

```bash
pnpm add -D @goodbones/campaigns   # required: the campaigns family
pnpm add -D @goodbones/ast-grep    # only if an objective uses a `syntax` term
```

`@goodbones/cli`, `@goodbones/oxlint` and `@goodbones/browser` each pick up
`@goodbones/campaigns` and `@goodbones/ast-grep` when they are installed, and run without them
when they are not. Without `@goodbones/campaigns`, a manifest with a `campaigns` key fails to
load and names the package to install. Without `@goodbones/ast-grep`, an objective that uses a
`syntax` term does the same.

The CLI runs `check`, the ledger commands and the nudge. The plugin flags new holdouts in the
editor.

:::caution
`@goodbones/ast-grep` ships a prebuilt binary as an optional dependency. Installing with
`--no-optional` or `--omit=optional` leaves it without that binary, and install fails on a
platform with no prebuilt binary. Skip the package if no objective uses `syntax`.
:::

## Enable the editor rule

```json
// .oxlintrc.json
{
  "jsPlugins": [{ "name": "architecture", "specifier": "@goodbones/oxlint" }],
  "rules": {
    "architecture/campaigns": "error"
  }
}
```

The rule reports a holdout the ledger does not already record. It stays quiet about recorded
ones. If `@goodbones/campaigns` is not installed, the rule reports that once, on the first file
it lints.

## Write a campaign and its first ledger

Add a `campaigns` key to `architecture.yaml`. Start from the
[smallest campaign](/goodbones/campaigns/getting-started/introduction/#the-smallest-campaign).
Every `match` objective needs a probe it fires on, or the policy refuses to load.

```bash
pnpm exec architecture objectives clear   # record every place each objective fires today
pnpm exec architecture check              # from now on, the count may only go down
```

`objectives clear` writes one JSON file per objective under `.architecture-campaigns/` (the
manifest's `ledger` key moves it). **Commit that directory.** Until it exists, `check` fails
and names the command to run.

To route ledger changes to the campaign's owner:

```
# CODEOWNERS
.architecture-campaigns/billing-ddd/  @your-org/billing
```

## Run the nudge

The [nudge](/goodbones/campaigns/running/nudge/) only appears where something runs it:

- **Before an agent finishes.** A stop hook, or a line in `CLAUDE.md` / `AGENTS.md`, runs
  `architecture campaigns status --changed --json`. It exits non-zero on any verdict other
  than `ok` or `hotfix`, so a hook can block on the exit code.
- **In CI.** Run it against the base branch, and `check` to hold every ledger:

```bash
pnpm exec architecture check
pnpm exec architecture campaigns status --changed --base origin/main
```

## Embed the loader

Skip this unless you call `loadPolicy` yourself instead of using the CLI or plugin. Pass the
campaigns extension, then read its state back:

```ts
import { campaignsExtension, campaignsOf } from "@goodbones/campaigns";
import { loadPolicy } from "@goodbones/core";

const policy = loadPolicy({
  // …
  extensions: [campaignsExtension({ functions, reports })],
});

const { campaignRules, ledgers } = campaignsOf(policy);
```

Without the extension, the `campaigns` and `ledger` keys are refused as unknown. A host that loads
the package only when it is installed can make that error name the package instead:

```ts
import { importOptional, loadPolicy } from "@goodbones/core";

const campaigns = await importOptional(
  () => import("@goodbones/campaigns"),
  "@goodbones/campaigns",
);
const policy = loadPolicy({
  // …
  extensions: campaigns === null ? [] : [campaigns.campaignsExtension({ functions, reports })],
  uninstalled:
    campaigns === null
      ? [{ manifestKeys: ["campaigns", "ledger"], install: "@goodbones/campaigns" }]
      : [],
});
```

`importOptional` returns `null` only when that package itself is missing. A package that is
installed but cannot load is still an error.

A campaign with a `syntax` term is refused at load when the term's language has no syntax
matcher. For TypeScript, build the pack with `typescriptLanguage({ syntax: astGrepMatcher() })`
from `@goodbones/ast-grep`.
