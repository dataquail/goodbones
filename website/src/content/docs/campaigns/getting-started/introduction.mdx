A campaign tracks a refactor too big for one change. Use one to count the remaining work,
stop it from growing, and tell whoever edits the code what's left.

Say your team is moving 140 React class components to hooks. A campaign records all 140,
fails `check` if a new one appears, and can tell anyone editing a file that still has one.

## Terms

| Term                                                   | Meaning                                                                                                    |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| campaign                                               | One refactor, written under `campaigns` in [`architecture.yaml`](/goodbones/architecture-rules/manifest/). |
| [objective](/goodbones/campaigns/manifest/objectives/) | A pattern the code is moving away from (or a thing it must come to have), or a number to reach.            |
| [ledger](/goodbones/campaigns/running/ledger/)         | A committed file listing every place an objective still fires; it may only shrink.                         |
| holdout                                                | One entry in a ledger: a place the refactor has not reached yet.                                           |
| [sector](/goodbones/campaigns/manifest/sectors/)       | A piece of code that moves through the campaign as one, such as a folder or a file.                        |
| [phase](/goodbones/campaigns/manifest/phases/)         | A named step of the refactor; a sector's phase is the first one it has not finished.                       |
| [nudge](/goodbones/campaigns/running/nudge/)           | `architecture campaigns status --changed`: what the files you touched owe the campaign.                    |

You never set a sector's phase. It is the first phase whose objectives still have holdouts in
that sector, so progress comes from the code.

## Plan only what you know

The last phase may be **open**: an `intent` in prose, with no objectives. Phases before it are
enforced. When you learn the next step, write it as a defined phase. Changing a defined phase
later needs a recorded reason (see [Phases](/goodbones/campaigns/manifest/phases/)).

## Steps a detector cannot see

Some steps are judged, not detected: a backfill that ran, invariants that moved into an
aggregate. A phase with `attested: true` holds such a step, and a sector leaves it when someone
records that it is done. The vocabulary was built for refactors that are mostly judgment, not
only for import bans; [Attested phases](/goodbones/campaigns/manifest/attested/) writes one out.

## The smallest campaign

One objective, no sectors, no phases. Goodbones runs this one on itself:

```yaml
campaigns:
  lowering-reports-not-throws:
    why: "`loadPolicy` returns a `Result`, but a manifest that lowers badly escapes it as a thrown `Error`."
    how: "Return `Result.fail(new ConfigInvalid({ configPath, detail }))` and let `loadPolicy` pass it up."
    owner: "@dataquail"
    scope: ["packages/core/src/manifest/**"]
    staleAfter: 90d
    objectives:
      throws-in-lowering:
        holdout: match
        match:
          all:
            - path: { file: "\\.ts$", fileNot: "\\.test\\.ts$" }
            - syntax: { pattern: "throw new Error($$$)" }
        probes:
          fires:
            - path: packages/core/src/manifest/zzprobe.ts
              source: 'const lower = () => { throw new Error("bad manifest"); };'
          ignores:
            - path: packages/core/src/manifest/zzprobe.ts
              source: "const lower = () => Result.fail(new ConfigInvalid({ configPath, detail }));"
```

[Defining a campaign](/goodbones/campaigns/manifest/) shows the full shape.

## A campaign does not

- Rewrite code. Use a codemod for that.
- Run tests, trace runtime behavior or span repositories.
- Change coverage or residue numbers.
- See files the language pack skips (TypeScript walks `.ts`, `.tsx`, `.mts`, `.cts`), unless
  its `scope` adds them.
