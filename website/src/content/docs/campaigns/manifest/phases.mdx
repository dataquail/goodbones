---
title: Phases
description: Ordered steps a sector moves through, each recognized by its objectives.
---

A phase is a named step in a campaign, recognized by the objectives it lists. Use phases when a
refactor happens in stages.

```yaml
phases:
  - { id: repository, objectives: [no-raw-queries-outside-repository] }
  - { id: dual-write, objectives: [has-flag] }
  - { id: backfilled, attested: true, intent: The backfill has run against production. }
  - { id: cutover, objectives: [no-flag] }
  - { id: aggregates, intent: Model refunds and disputes inside the billing aggregate. }
```

| Field         | Meaning                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------ |
| `id`          | kebab-case                                                                                             |
| `intent`      | what the phase is for, in prose. Shown wherever the phase is named; required on an open one            |
| `objectives`  | the objective ids that recognize this phase                                                            |
| `attested`    | `true` for a step no detector can see; left with `campaigns attest`                                    |
| `onTouch`     | overrides the campaign's [`onTouch`](/goodbones/campaigns/running/nudge/) for this phase               |
| `grows`       | scalar objective ids this phase is expected to raise; see [A phase that grows](#a-phase-that-grows)    |
| `endState`    | a node tree for the sector; see [The end state](#the-end-state)                                        |
| `concessions` | `[{ reason, at, by? }]`, required when a defined phase changes; see [below](#changing-a-defined-phase) |

A phase is **defined** when it has objectives, `attested`, or an `endState`. It is **open** when it
has only an `intent`, and an open phase must be last. The loader refuses an open phase that is not
last, an objective listed by two phases, and an objective id the campaign does not declare.

## A sector's phase

A sector's phase is derived, never set: it is the first phase that still has work for that
sector (a holdout, a missing attestation, or an open phase). A sector past the last defined phase
is done. `objectives clear` records `reached`, the furthest phase a sector has been at.

## Windows

An objective counts for a sector from the phase that lists it until the phase its `until` field names
(exclusive), or to the end. Use a window for a temporary shape, such as a flag that must exist
during `dual-write` and be gone from `cutover`.

- Entering a window, `objectives clear` records the sector's count as `initial`, not a regression.
- Leaving one, remaining holdouts become `closed`. That is not progress and doesn't reset the stall
  clock.
- A window ending at or before the sector's `reached` never reopens for it.

The loader refuses an `until` naming an unknown phase, or one at or before the listing phase.

## A phase that grows

Some steps make a number worse before it gets better: a dual-write adds lines to the module it
will later delete. Say so on the phase, and the rise is not refused:

```yaml
phases:
  - id: mirrored
    intent: Every write is mirrored to the new server.
    objectives: [writes-not-mirrored]
    grows: [legacy-lines]
```

While a sector stands in that phase, a rise of `legacy-lines` past its tolerance is not growth
to concede. `check` reports the ledger as behind and asks for `objectives clear`, which records
the rise with a receipt naming the phase (`phase mirrored grows legacy-lines`). The nudge prints
`grows in mirrored` beside the number, and does not call it `back`.

- The phase is the one the sector stood at before the change, so the change that completes the
  phase is covered too.
- Everywhere else the scalar ratchets as before, including at the open phase.
- `grows` takes [scalar objectives](/goodbones/campaigns/manifest/scalars/) only. A holdout is
  conceded by name, with a reason.
- The loader refuses `grows` on an open phase, and an objective that is not in window at the
  phase.
- `grows` is part of what a phase asks, so adding or removing it on a defined phase
  [needs a concession](#changing-a-defined-phase).

`onTouch: advise` does not do this. It quiets the nudge and nothing else: `check` still wants a
rise conceded.

## Attested phases

A phase with `attested: true` has no detector: it is a step a person judges done, such as a
backfill that ran or invariants that moved into an aggregate. A sector leaves it with:

```bash
architecture campaigns attest <sector> <phase> --reason "<why>" [--evidence <url>]
```

It is accepted only while the sector is at that phase. The nudge and `explain` name the phase as
attested and print the command. [Attested phases](/goodbones/campaigns/manifest/attested/)
writes out a refactor that is mostly judgment.

## Open phases

An open phase is where the plan runs out. The nudge shows its `intent`; anyone can leave a note:

```bash
architecture campaigns note <sector> "refunds read invoices but never write them"
```

Adding its first objective later is free (**plan refined** in the conformance report).

## Changing a defined phase

Changing what a defined phase asks fails `check` until the phase carries a new `concessions`
entry. That is its objectives, an objective's detector, `attested`, `grows` or its `endState`.
Moving a phase past another one is a change to the phase that moved, because the order is what
a sector is asked first.

Inserting a phase changes no other phase, and neither does rewording an `intent`.

```yaml
- id: repository
  objectives: [no-raw-queries-outside-repository]
  concessions:
    - { reason: "detector widened to catch knex calls", at: "2026-10-02", by: someone@example.com }
```

The next `objectives clear` re-baselines the affected sectors, recording `{ from, to, reason }` in
each ledger. `check` compares against the last [plan](/goodbones/campaigns/running/ledger/) `clear`
wrote.

## The end state

`endState` is a node tree whose root `~/` is the sector. It expands into objectives named
`end-state-<family>` (`imports`, `members`, `surface`, `structure`, `exports`), each with
`holdout: declaration`. Write it on a phase, or on the campaign for the last phase (a campaign
with no phases gets one named `end`).

```yaml
endState:
  ~/:
    surface: [{ message: "no default exports", kinds: [default] }]
    children:
      "domain/": { layout: open, children: {}, imports: { allow: ["~/domain/**"] } }
      "ports/": { layout: open, children: {}, imports: { allow: ["~/domain/**"] } }
      "adapters/":
        layout: open
        children: {}
        imports: { allow: ["~/ports/**", { sector: "*", via: "~/ports/" }] }
```

- `{ sector, via }` allows imports from another sector (`*` for any) through its `via` folder.
- An end state needs sectors with one root: use a `glob`, `file` or `nx` perimeter. The loader
  refuses one over a `marker` perimeter, whose sectors may have several roots.
- Only the CLI evaluates an end state.
