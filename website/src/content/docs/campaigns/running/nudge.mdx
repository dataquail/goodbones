---
title: The nudge
description: Tell whoever touches a sector which campaign applies and what to do next.
---

The nudge tells you, or an agent, when a diff touches code under a campaign: which campaign, what
phase that sector is at, and what small change would move it forward. Run it from a stop hook or
in CI.

```bash
architecture campaigns status --changed [--base <ref>] [--json] [--hotfix "<reason>"] [--by <email>]
```

It reads the working-tree diff against `HEAD`, or against `--base <ref>`. See
[Commands](/goodbones/campaigns/running/cli/) for the flags.

## Output

At a **defined phase**, it lists what is left and the holdouts nearest your change:

```
billing-ddd
  billing — phase repository (2 of 6), 9 days here
    intent: a repository behind a port
    toward the next phase: no-raw-queries-outside-repository 7 · has-integration-test 1
      no-raw-queries-outside-repository — A query outside the repository is one the port cannot see.
      has-integration-test — A context with no integration test cannot be cut over safely.
    of the sector as a whole:
      has-integration-test: Add an integration test for the context.
    in the files you touched, nearest your change (2 of 2; 8 in the sector):
      src/billing/InvoiceService.ts#reconcile:41  no-raw-queries-outside-repository
      src/billing/InvoiceService.ts#void:58       no-raw-queries-outside-repository
    this diff: −no-raw-queries-outside-repository: InvoiceService.ts#refund#4b02a9e1  forward
    onTouch: ratchet — ok
    ask: hold — leave the sector no worse; paydown is welcome in its own commit, not asked for

ok
```

The phase's `intent` is printed wherever one is stated, and each objective's own `intent`
beside its count, so the why is read where the check is. A holdout of the sector itself
(`holdout: sector`) has no file, so it is listed apart from the files you touched. When the
sector's marker owns a glob that no file matches, that is said there too: it is a folder not
written yet, or a typo.

When the diff **moves the sector on**, the next phase's objectives come into window. What they
count was there all along, so it is listed as now counted, and it is not growth:

```
strangle-hapi
  todo — phase routes-moved (6 of 9)
    this diff moves it from served: it is judged by the phase it was found at
    toward the next phase: no-hapi-routes 2
    this diff: −routes-still-local: todo-routes.ts#todoRoutes#9c1e44d0  forward
    now counted: no-hapi-routes 2 — in window from routes-moved, not growth
    hapi-lines: recorded 454 → now 93 (tolerance 20)
    onTouch: ratchet (of served) — ok
    ask: hold — leave the sector no worse; paydown is welcome in its own commit, not asked for

ok
```

When the diff touches the **shared files**, which every sector shares, the nudge says what it
still owes and who is waiting:

```
strangle-hapi
  shared — held by every sector, on no phase
    prerequisites, which hold every sector at the phase that names them:
      has-user-authenticator 1 — rebuilt: todo, user
    hapi-lines: recorded 61 → now 80  measured, not held
    onTouch: advise — ok
    ask: none — the holdouts above are context; paydown is welcome in its own commit, not asked for
```

A sector waiting on a prerequisite lists it under "toward the next phase", marked as the
shared files' to meet. See [The shared files](/goodbones/campaigns/manifest/sectors/#the-shared-files).

At an **attested phase**, nothing is detected, so the sector is never quiet: the nudge names the
phase as attested and prints the command that leaves it. See
[Attested phases](/goodbones/campaigns/manifest/attested/).

```
billing-ddd
  billing — phase backfilled (4 of 6, attested), 2 days here
    intent: legacy rows copied and verified
    this phase is attested, not detected: no objective sees it done. When it is, record it —
      architecture campaigns attest billing backfilled --reason "…" [--evidence <url>] --campaign billing-ddd
    onTouch: ratchet — ok
    ask: hold — leave the sector no worse; paydown is welcome in its own commit, not asked for
```

At an **open phase**, it shows the `intent` and notes, and asks you to refine the phase or leave a
note:

```
billing-ddd
  billing — phase aggregates (6 of 6, open), 4 days here
    intent: Model refunds and disputes inside the billing aggregate.
    notes (1, data, left at this phase): 2026-10-04 "refunds read invoices but never write them"
    if this change taught you something about that shape: refine phase `aggregates` in the manifest
    (a defined phase needs at least one objective with a probe), in its own commit — or leave a note:
      architecture campaigns note billing "…" --campaign billing-ddd
    onTouch: advise — ok
    ask: note
```

With nothing to say, a sector gets one line. It shows at most five holdouts per sector from the
files you touched, nearest first: `match` and `declaration` holdouts by distance from your change,
then `file` holdouts. The last line is `ok` or `not ok`.

## Before and after

"Before" is the ledger as of the last `objectives clear`; "after" is your working tree. A holdout
you fixed but haven't cleared counts as progress, and one the ledger already carries is not growth.
A file the diff deletes touches the sector it stood in (the one with the deepest root above it),
so the diff that finishes a sector by deleting its files is shown and counted like any other.

In CI, use `--base <ref>`: the base commit is checked out and evaluated, including rerunning
`report` tools. Results are cached per commit under `node_modules/.cache/goodbones/`. A scalar
then prints the base tree's value with the ledger's record beside it
(`402 → 409 (recorded 400, tolerance 20)`); without `--base` the record is the "before", and the
line says so (`recorded 400 → now 409`).

**A diff is judged by the phase the sector stood at before it.** That is the base tree's phase
with `--base`, and the phase the ledgers place the sector at otherwise (an objective the sector has
no ledger entry for counts as met only up to the phase it has `reached`). Only the objectives in
that phase's window are scored, and that phase's `onTouch` is what applies. So the diff that
finishes a phase is judged by the phase it finished, not by the next one, and a phase whose
`onTouch` is `advise` covers its own last change.

**An open phase is no gap in the ratchet.** The windows still open at an open phase are earlier
phases' objectives, and each count that got worse there is held by the phase that lists the
objective: under its `ratchet` or `paydown` the verdict is `back`, though `ask` stays `note`. The
nudge says which held it (`went back at an open phase, held by the phase that named it: no-models
(moved, ratchet)`), and `held[]` in the JSON lists them.

**A concession is a receipt in both modes.** Growth that `objectives concede` recorded on the
branch is in the head's ledger, with its reason. With `--base` it is printed as conceded rather
than added, and it does not make the verdict `back`.

## `ask` and `verdict`

Hooks should read these two fields, not the prose.

| `ask`              | When                                                                   |
| ------------------ | ---------------------------------------------------------------------- |
| `none`             | under `advise`; the holdouts are context only                          |
| `note`             | the sector's phase is open                                             |
| `hold`             | under `ratchet`: leave the sector no worse                             |
| `paydown-optional` | under `paydown`, when the diff edits no declaration carrying a holdout |
| `paydown-required` | under `paydown`, when it does: the sector must end with fewer holdouts |

| `verdict`    | Meaning                                                       | Exit     |
| ------------ | ------------------------------------------------------------- | -------- |
| `ok`         | the policy is met                                             | 0        |
| `hotfix`     | growth let through with `--hotfix`, and recorded              | 0        |
| `back`       | some objective's count got worse under `ratchet` or `paydown` | non-zero |
| `no-paydown` | `paydown-required`, and the sector did not shrink             | non-zero |

`direction` is **forward** (nothing worse, something better), **back** (the reverse), **mixed**
or **neutral**. Counts are compared per objective, never summed. The verdict and the direction are
read off the same judgement: a `back` verdict always comes with a `back` or `mixed` direction, and
under `ratchet` or `paydown` those two directions always give a `back` verdict.

## `onTouch`

`onTouch` sets what a touched sector must do. Set it on the campaign, and override it per phase.

- **`advise`**: nudge only. `onTouch` governs the nudge and nothing else: new holdouts still fail
  `check` until conceded. Default for open phases.
- **`ratchet`**: any count getting worse in a touched sector fails, until the growth is fixed or
  conceded with a reason. `--hotfix "<reason>"` concedes it in the same run. Moving a holdout to a
  neighbouring sector sends that sector back instead. Default for defined phases.
- **`paydown`**: `ratchet`, plus a diff that edits a declaration carrying a holdout must leave the
  sector with fewer holdouts.

A [scalar objective](/goodbones/campaigns/manifest/scalars/) goes back only when it worsens past
its tolerance, and `paydown` treats it as `ratchet`. Scalars are listed under `measures`. A rise
in a phase that [`grows`](/goodbones/campaigns/manifest/phases/#a-phase-that-grows) the scalar
is not `back`: the line reads `grows in <phase>`, and `measures[].grows` is `true`.

## JSON

`--json` prints one document for a hook or PR comment:

```json
{
  "version": 1,
  "mode": "ledger",
  "base": null,
  "touched": ["src/billing/InvoiceService.ts"],
  "sectors": [
    {
      "campaign": "billing-ddd",
      "sector": "billing",
      "phase": {
        "id": "repository",
        "index": 1,
        "of": 6,
        "open": false,
        "attested": false,
        "since": "2026-09-22T00:00:00.000Z"
      },
      "judged": { "id": "repository", "index": 1 },
      "intent": "a repository behind a port",
      "objectives": [
        {
          "id": "no-raw-queries",
          "intent": "A query outside the repository is one the port cannot see."
        }
      ],
      "notes": [],
      "onTouch": "ratchet",
      "ask": "hold",
      "verdict": "ok",
      "residue": { "before": { "no-raw-queries": 8 }, "after": { "no-raw-queries": 7 } },
      "direction": "forward",
      "toward": { "no-raw-queries": 7 },
      "holdouts": {
        "total": 8,
        "touched": 1,
        "cap": 5,
        "shown": [
          {
            "file": "src/billing/InvoiceService.ts",
            "subject": "reconcile#3bfd86f4",
            "objective": "no-raw-queries",
            "line": 41,
            "message": "Move the call behind the port."
          }
        ],
        "sector": []
      },
      "added": [],
      "removed": ["no-raw-queries: InvoiceService.ts#refund#4b02a9e1"],
      "conceded": [],
      "entered": [],
      "measures": [],
      "belongsInSector": [],
      "unmatchedOwns": []
    }
  ],
  "unbirths": [],
  "testsChecked": "unknown",
  "ok": true
}
```

- `intent`: the phase's, at any phase that states one; `objectives`: those in `toward`, each
  with its own `intent` (`null` where it states none).
- `phase.attested`: the sector waits on `campaigns attest`; nothing in the diff can move it.
- `phase` is where the sector stands with the diff applied; `judged` is where it stood before,
  which is the phase whose window fills `residue` and whose `onTouch` is reported.
- `entered`: objectives that came into window because the diff moved the sector on, with what
  each counts. They are in no dimension of the verdict.
- `holdouts.total` counts every holdout in window in the sector and `holdouts.touched` those in
  the files the diff touched; `shown` is the nearest of those. `holdouts.sector` lists holdouts
  of the sector itself, which have no file.
- `conceded`: with `--base`, growth against the base tree that the head's ledger carries.
- `measures`: each scalar's `before`, `after` and `recorded` (what the ledger holds the sector
  to), with `back` for a rise past the tolerance that no record covers, `conceded` for one a
  record does, and `grows` for one the judged phase expects.
- `belongsInSector`: files the diff added inside the scope that no sector claims.
- `shared`: `true` for the campaign's shared files, whose `phase.id` is `null`. `prerequisites`
  lists each objective read over it, with its count, the phase naming it and the sectors
  `waiting` there. An entry of `objectives` with `shared: true` is a prerequisite the sector
  waits on.
- `unmatchedOwns`: globs the sector's marker owns that no file matches.
- `unbirths`: markers the diff deleted, and the sector each returns to the legacy.
- `testsChecked`: always `unknown`; the tool runs no tests. The text output no longer prints it.

## Wiring it in

Run `status --changed --json` from a stop hook or a `CLAUDE.md` instruction before an agent
finishes, and post it as a PR comment in CI. The oxlint plugin doesn't nudge; it only reports
holdouts missing from the ledger.

:::tip
Put paydown, and any plan refinement an open phase asks for, in their own commits so reviewers can
separate them from the feature.
:::
